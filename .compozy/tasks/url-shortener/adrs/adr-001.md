# ADR-001: Stack — Node.js + TypeScript + Fastify + better-sqlite3 + Vitest

## Status

Accepted

## Date

2026-09-21

## Context

Desafio de entrevista ao vivo, 1h cronometrada, avaliação foca em resultado (funciona,
testado, roda) e processo. Stack é livre, mas precisa ser justificada no momento da
escolha. Precisamos: API HTTP simples, persistência com agregação (cliques por dia,
top referrers), testes determinísticos rápidos, zero fricção de setup (subir com um
comando, sem depender de Docker/serviço externo).

## Decision

Node.js + TypeScript, framework HTTP Fastify, persistência SQLite via `better-sqlite3`
(driver síncrono, sem pool assíncrono), testes com Vitest. Página de analytics
server-rendered (HTML gerado no backend), sem framework de frontend nem build step
separado.

## Alternatives Considered

### Alternative 1: Postgres + Prisma

- **Descrição**: banco relacional completo com ORM.
- **Prós**: mais próximo de produção real, migrations tipadas.
- **Contras**: exige subir container/serviço externo, mais fricção de setup, mais
  superfície pra travar em 1h.
- **Por que rejeitado**: viola o requisito não-funcional de "roda com um comando" sem
  dependência externa; overhead não se paga no tempo disponível.

### Alternative 2: Em memória (Map/array)

- **Descrição**: sem persistência real, tudo em processo.
- **Prós**: zero setup, mais rápido de escrever.
- **Contras**: não sobrevive a restart, agregações (`clicksByDay`, `topReferrers`)
  viram loop manual em vez de query, mais difícil de testar isolando estado.
- **Por que rejeitado**: persistência real é mais barata de justificar tecnicamente
  (SQL faz a agregação) e SQLite com `better-sqlite3` tem custo de setup quase igual
  a zero.

### Alternative 3: Next.js full-stack (frontend com build)

- **Descrição**: app único com API routes + página React para analytics.
- **Prós**: um único processo, ecossistema maduro de gráficos (recharts etc.).
- **Contras**: build step, mais tempo de setup, mais superfície de configuração
  (SSR, roteamento) irrelevante pro escopo do desafio.
- **Por que rejeitado**: analytics visual não exige interatividade rica; HTML
  server-rendered com tabela/gráfico simples (SVG inline ou barras CSS) entrega o
  requisito sem build de frontend.

## Consequences

### Positive

- Setup e start em segundos, sem serviço externo.
- SQLite resolve `clicksByDay`/`topReferrers` com `GROUP BY` nativo.
- `better-sqlite3` é síncrono → testes determinísticos sem mock de I/O assíncrono.
- TypeScript dá tipagem no contrato dos endpoints sem esforço extra.

### Negative

- SQLite não escala horizontalmente (não é requisito do desafio).
- Página de analytics sem gráfico interativo rico (aceitável: requisito pede "gráfico
  ou tabela").

### Risks

- Nenhum bloqueante identificado para o escopo de 1h.

## Implementation Notes

- Banco de dados em arquivo (`./data/url-shortener.sqlite`), path configurável via
  `DATABASE_URL` (ver `.env.example`).
- Testes usam banco SQLite em memória (`:memory:`) para isolamento e velocidade,
  sem tocar o arquivo real.
